# PRD Validation Gap Matrix

Scope: documentation-only status map for PRD gaps that still need explicit validation evidence.
This file links PRD requirements to current files and tests without changing production code.

## Latest Implementation Notes

- MCP/CLI surface now includes typed REST wrappers for Mail, Drive, Docs, Chat, Calendar, and Meet.
  Docs wrappers cover `docs create`, `docs update-title`, `docs export`, and
  `docs comment-create`/`docs comment`; Chat wrappers cover `chat send`, `chat create-room`, and
  `chat search`/`chat list`; Calendar wrappers cover create/update/delete/respond and find-time
  operations; Meet wrappers cover create/list/mint-token/end-room with backend-schema-aligned
  payloads. Completion scripts expose the same typed flags.
- The CLI now maps `helix tier set <personal|business|enterprise|sovereign>` to the existing
  `PATCH /api/admin/platform-config` tier update path, with parser/client/completion tests.
- The CLI now accepts `HELIX_TRACE_TOKEN` and attaches a W3C `traceparent` header to REST,
  OAuth form, and MCP requests, giving live admin/API/MCP evidence a shared trace id.
- Agents can now poll generic confirmation-gated tool status through `GET /actions/:id` or
  `GET /api/actions/:id`, with OpenAPI documentation and `helix action status <id>` CLI evidence.
- MCP now advertises `resources` capability and handles `resources/list` plus `resources/read`.
  The live `/mcp` route uses actor-scoped Chat, Calendar, Mail, Drive, and Docs stores directly,
  while the search-backed projection remains covered for indexed resource clients. The CLI also
  exposes `helix mcp resources list` and `helix mcp resources read <uri>`.
- Audit hash-chain verification is now deterministic and offline-testable through
  `verifyAuditHashChain`, covering valid chains, broken previous links, tampered record hashes, and
  empty-chain behavior. The bundled audit Grafana dashboard now includes activity rate,
  hash-chain failure/last-verified panels, immutable shipping lag, and shipping backlog metrics.
  `AuditVerifierWorker` provides the PRD daily verifier job with per-org reporting,
  non-overlapping scheduled runs, optional Postgres advisory leader locking, and offline tests.
- The bundled Grafana stack now includes a Signup dashboard over
  `helix_signup_funnel_events_total` and `helix_signup_activation_duration_seconds_*`,
  covering commercial operations dimensions `step`, `tier`, `plan_id`, `region`, and
  `within_target` without tenant, actor, email, token, IP, URL, or user-agent labels.
  The local Prometheus config now loads bundled signup activation SLO alert rules for
  p95 latency, SLO miss rate, and submitted-signup-without-activation samples, and
  `pnpm quality:synthetic-signup-probe` adds Mailpit-backed synthetic activation evidence.
  `pnpm quality:alertmanager-signup-routing` proves the bundled/local Alertmanager
  signup SLO route. A production Alertmanager overlay now fans the same signup
  activation alerts to `helix-signup-slo-paging` via a deployment-mounted
  `url_file`, with static validation covering the secret-file contract. Real
  external paging delivery with live PagerDuty/Opsgenie/BetterStack credentials
  remains release/deployment evidence.
- Tenant feature flags now live-gate tool listing and invocation through the
  runtime tool registry. The first kill switches cover outbound mail,
  B2B Drive sharing, and Docs/Sheets/Slides native editor tool families; tenant
  config feature edits publish `flags.changed.<orgId>` events for future cache
  invalidation subscribers.
- Webhook verification docs are served at `/docs/webhooks/verify` and mirrored in
  `docs/webhooks/verify.md`, with JS, Python, Go, Ruby, and PHP snippets for
  `X-Helix-Signature: t=<timestamp>,v1=<hex>` HMAC-SHA256 verification.
- The `/assistant` shell route now uses a TanStack Router loader to prefetch the assistant
  conversation query before the page mounts, keeping the route aligned with the PRD loader pattern
  for data-driven surfaces.
- Runtime REST and tRPC tool-list projections now expose `rateLimit` and
  `estimatedCostUsdMicros`, keeping live agent catalog metadata aligned with OpenAPI and MCP.
- Webhook administration now has typed CLI wrappers for outbound, inbound, and delivery tools, and
  outbound delivery enforces a conservative `metadata.classificationPolicy.blockedClassifications`
  policy before live dispatch, retry dispatch, or replay.
- Inbound webhook routes now verify provider signatures against the exact raw request bytes instead
  of parsed/re-serialized JSON, preserving GitHub/Stripe/Linear/generic HMAC interoperability.
- CalDAV `PROPFIND` now returns discovery-oriented collection/principal properties including
  `current-user-principal`, `calendar-home-set`, `resourcetype`, component support, depth handling,
  event `getetag` members, and `supported-report-set` advertisement for `calendar-query` and
  `calendar-multiget`.
- CalDAV now supports `REPORT calendar-multiget` responses, including per-href `404` entries for
  missing resources, emits `ETag` headers on event `GET`, and enforces CalDAV `PUT`/`DELETE`
  `If-None-Match` and `If-Match` preconditions in focused route tests.
- CalDAV PUT/GET now round-trips `TZID` local wall-clock `DTSTART`/`DTEND` values, normalizes
  `TZID` `EXDATE` and cancelled `RECURRENCE-ID` values to UTC recurrence exceptions, and emits
  non-UTC timed ICS invitations with `TZID`. CalDAV now also round-trips all-day
  `DTSTART;VALUE=DATE`/`DTEND;VALUE=DATE` events through `PUT`, `GET`, ICS emission, and
  `calendar-query` date-only windows.
- Calendar RSVP handling now queues organizer-directed `METHOD:REPLY` iTIP mail through the same
  mail outbound path for authenticated responses and public RSVP links, and malformed RSVP links
  return deterministic `400` responses without mutating attendee state. Authenticated Calendar RSVP
  responses now also append Calendar activity/outbox events without exposing RSVP tokens in the
  event payload.
- CalDAV app-password auth now uses method-specific scopes: read/discovery methods require
  `calendar.read`, while `PUT` and `DELETE` require `calendar.write` unless the app password has
  the `caldav` compatibility scope.
- App-password lifecycle management is now exposed through `app.passwords.list/create/revoke`,
  wired into the server registry with Postgres and in-memory stores, surfaced in `/admin`, and
  wrapped by `helix admin app-passwords list/create/revoke` for CalDAV/WebDAV/IMAP-style clients.
- WebDAV compatibility is now wired at `/dav/files/*` over the Drive store with Basic
  app-password auth, method-specific `drive.read`/`drive.write`/`drive.delete` scopes, `webdav`
  compatibility scope, `PROPFIND` listing with nested child href preservation, requested property
  filtering, `propname`, real exclusive write `LOCK`/`UNLOCK` token handling, active
  `lockdiscovery`, supported lock advertisement, deterministic quota properties,
  unsupported-property `404` propstats, nested `GET`/`PUT` path resolution, `GET` download when
  object bytes are available, `MKCOL` folder creation with nested location preservation, file
  `DELETE` via Drive trash semantics, recursive collection `DELETE` via `drive_folders.deleted_at`
  plus descendant file soft-trash/docs sync, root collection safety responses, and `PUT`
  `If-None-Match`/`If-Match` precondition enforcement.
- Plugin lifecycle controls now extend the plugin admin surface with `plugin.enable`,
  `plugin.disable`, and confirmation-backed `plugin.uninstall` tools, CLI aliases, and admin table
  actions over the existing plugin catalog.
- CardDAV compatibility now backs `/dav/card/*` with migrated contacts, Basic app-password auth,
  method-scoped `carddav.read`/`carddav.write` or `carddav`, `PUT` upsert, read listing, and
  soft-delete removal. `sync-collection` is backed by persisted `sync_version` state and returns
  true deltas: empty current-token responses, updated-contact responses, and deleted-contact
  tombstone `404` responses. Discovery now advertises `addressbook-query`,
  `addressbook-multiget`, and `sync-collection`, and `addressbook-multiget` returns per-href
  `404` multistatus entries for missing contacts.
- Inbound webhook source coverage now includes GitLab, Grafana, and Prometheus/Alertmanager
  adapters alongside GitHub, Stripe, Linear, and generic sources, with source-specific verification
  and admin test-probe payloads.
- Assistant AI routing now wires an AI cost guard around provider calls so over-budget turns are
  blocked before provider invocation and completed calls are recorded against the limiter.
- Mail and Chat routes now use route search params plus TanStack Router loaders for the same
  search/list/message queries their shells consume, and Docs route loading now prefetches the
  document list before the shell mounts.
- Drive and Meet routes now also derive list filters from route search params and prefetch the same
  query inputs their shells consume.
- Webhook administration now uses step-based outbound/inbound create-edit flows with review
  summaries and local validation before mutation dispatch; the delivery log now supports webhook-id
  and time-range filters plus explicit row detail selection.
- Browser ESLint rules now enforce the native-popup ban and the Section 11 query discipline
  requiring `useQuery` calls to consume feature `queryOptions` factories and direct query refreshes
  to use query invalidation helpers instead of `.refetch()` calls.
- Calendar route state now covers selected event, active date, view, and query, with the loader
  prefetching the same event-list window used by the shell.
- Admin readiness routes now preload both platform configuration and plugin catalog queries before
  mounting the admin UI.
- Admin tier updates now enforce readiness gates on backend-owned upgrades and return a
  conflict response with the missing gates when a target tier is not ready.
- Plugin signature evidence now requires a strict `sha256:<64 lowercase hex>` digest, verifies it
  against canonical plugin bundle bytes, and requires a trusted signer identity or Sigstore bundle
  before signature-required tiers accept a plugin.
- Mail, Chat, agent credential, and app-password refresh paths now use query invalidation instead
  of direct `refetch()` calls, and browser ESLint also bans raw internal `<a href>` navigation in
  favor of TanStack Router `Link`.
- Browser ESLint now enforces Section 11 mutation discipline by requiring direct `useMutation`
  calls to include both `onMutate` and `onError`; webhook management and admin readiness mutations
  use optimistic cache updates with rollback contexts.
- Shell sidebar/right-rail UI state now lives in a TanStack Store slice, login uses TanStack Form
  with Zod-backed field validation, and the command palette dialog includes hidden Radix title and
  description elements for screen-reader accessibility.
- Chat messages, Drive item views, command-palette search results, mail thread lists, and webhook
  delivery logs now render through TanStack Virtual coverage with jsdom-compatible focused tests.
- The `/search` shell route now validates query/type search params with Zod, prefetches
  `search.query` through its TanStack Router loader, and renders the full search results list with
  TanStack Query, TanStack Table, TanStack Virtual, and shared shadcn table primitives.
- Browser forms now apply Zod-backed TanStack Form field validation across login, Mail vacation
  settings, Chat compose/edit, Assistant compose, Drive sharing, Docs comments, Meet room creation,
  and outbound/inbound webhook wizards, with focused tests covering blocked invalid submissions and
  preserved valid submit flows.
- Browser code now uses TanStack Pacer for search-as-you-type and typing indicator pacing:
  command-palette global search, Mail search, Drive search, Calendar search, Meet room search, and
  Chat typing-stop dispatch are paced with `@tanstack/react-pacer`; browser ESLint enforces
  `helix/pacer-discipline` against native timer calls in production source.
- Drive list view, the admin plugin catalog/security-control tables, and Mail saved-filter
  management now use TanStack Table v8 headless row models wrapped in the shared shadcn table
  primitives while preserving existing virtualized/action flows; focused tests cover table
  headers, rows, selection, install/review, and filter update/delete actions.
- `/admin` now includes a read-only audit log table backed by `/api/admin/audit-log` over the
  existing `activity` table, an admin user directory backed by `GET /api/admin/users` over the
  existing `actors` table, and an agent OAuth credential management surface backed by
  `agent.credentials.list/create/revoke` and the shared pending-tool approval route.

- Mail density preference, thread/message multi-select UI state, and composer draft state now live

## Drive Storage Evidence Note

Drive byte-finalization evidence must prove both the default RustFS path and
tenant-resolved/BYO path. `drive.upload` may return `uploadUrl: null` when no
tenant or default object storage can be resolved, but `drive.finalize` with
`contentBase64` must reject instead of recording ready metadata without bytes in
object storage. BYO proof should include tenant resolver and
`credentials_vault_path` secret-reader coverage, not only default RustFS.
Staged BYO migration proof now also needs admin live-job validation for captured
source/target snapshots and worker resolution from those snapshots; atomic
tenant config swap, dual-write behavior, CLI coverage, and end-to-end live
migration evidence remain open. Sheets and Slides create paths now have
tenant-resolved snapshot write proof, including stored byte size/hash metadata;
native cell/tab/deck/slide mutations refresh the latest tenant-resolved
snapshot and shared object byte/hash metadata, and each create/mutation also
records an immutable `drive_versions` snapshot under
`sheets/<orgId>/<sheetId>/versions/<n>` or
`slides/<orgId>/<deckId>/versions/<n>`. End-to-end editor persistence and
restore-from-version evidence remain open.
