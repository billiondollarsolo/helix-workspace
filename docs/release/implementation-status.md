## Decisions

D1: invite-only Mail, Drive, Chat, Assistant, and Admin; Calendar and Meet remain dormant behind `full`. D2: the owner requested full removal of editors, superseding the scaffold option. D3: lucide. D4: built-in webhook formatters, without an installable plugin runtime. D5: Apache-2.0 alone.

## Logic review and runtime corrections

- Calendar pagination now counts visible occurrences, preserves rule/RDATE order, and includes extended overrides that overlap the query window. Scans remain bounded. Recurrence/free-busy/scheduling/routes: 4 files, 43 tests passed, including new cancelled-instance, RDATE, duration, and scan-bound regressions.
- Chat's active grant predicate covers tenant identity, active membership, expiry, future validity, revocation, and disabled subjects. Known-ID, discovery, mutation, and realtime denial tests passed; this focused review found no additional grant defect.
- Drive immutable version and quota flows retain shared authorization and atomic database accounting. The aggregate split preserved the public API. WebDAV collection reads now use the same advisory lock as journal updates instead of a row lock that triggered UPDATE RLS and hid collection state. The live journal regression passes.
- Mail delivery/read visibility now uses canonical delivery state. Explicit invalid thread IDs fail closed. Calendar invitations/replies no longer pass a Calendar-kind thread into Mail.
- Canonical domain creation supplies required ownership-challenge fields and uses the global claim constraint. Forward migration 0184 fixes Drive domain grants to use canonical verified status and reject a missing owner role. Live receiving-domain/ACL tests pass.
- Forward migrations 0185–0189 and associated fixes preserve restrictive tenant boundaries, tenant foreign keys, trusted attachment snapshots, raw-mail immutability compatibility, and correct WebDAV old/new audiences. Final all-migration/full-suite validation is recorded by the CI gate, not inferred from these focused results.

## Dependency corrections

Direct `@better-auth/utils` dependencies were removed in favor of Better Auth's supported `crypto` export. Password hashes remain compatible in both directions, including Unicode passwords and incorrect-password rejection. This retains Better Auth 1.7.2 and its declared utility version while `better-call` retains its own newer utility dependency.

A version-scoped `.pnpmfile.mjs` hook installs Zod 4.4.3 for `better-call` 1.4.0's OpenAPI code. Isolated installs demonstrated that pnpm 11.18's package extension and override approaches still bound the optional peer to application Zod 3; the hook converts it to a real dependency rather than suppressing the mismatch. The Docker dependency layers include the hook. The WASM runtime was updated to 1.2.2, which includes the upstream [emnapi v1 compatibility fix](https://github.com/napi-rs/napi-rs/pull/3426), and obsolete peer allowances were removed. The SDK web lucide peer now matches its direct dependency.

Generated third-party notices and the dependency license policy passed for all 9 manifests and 718 production packages.

## Remaining release operations

1. Review and push the local annotated candidate tag, run the remote CI/image gates, and dispatch the release workflow. Remote drafts and publication have not been performed. Focused or mocked tests do not replace live deployment evidence.
2. Deploy exact signed application/web OCI digests and collect the required live mail-provider, Drive, Chat load, agent, data-plane, restore, recovery, and DAST evidence. Complete the required real soak window and owner/support/business decisions.
3. Configure protected release trust, retain the bound evidence packet, create the signed final tag, and obtain the signed protected-Git-state observation and production decision. The workflow must pass `--final-release` before a final draft is eligible for publication.

A local candidate tag, package version `1.0.0`, passing unit tests, or a draft release does not satisfy the final production gate.
